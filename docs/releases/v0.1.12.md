## Forge Studio and ForgeInfer v0.1.12 (pre-release)

**"Summarize this file" now reads the whole file.** A question about a file that is too long for the context is answered from the passages that match it best, and a request to summarize matches nothing in particular: the answer came from the start of the file and a few weak matches. Now a request to summarize (a summary, an overview, key points, "what is this about") has the chat model read every file part by part (a part is at most 14,000 characters), write a short summary of each part, and answer from those summaries. A line under your question shows how far it is, **Stop** gives the question back, and the summaries are kept, so asking again about the same file costs nothing.

Measured with Qwen3.5-4B on an RTX 4060: the 88 KB QLoRA paper is seven parts and took 24 seconds, the answer then 7 seconds; a 16 KB paper is two parts and took 6 seconds. The summaries are only as good as the model that writes them (Qwen3-1.7B's are rougher than the 4B's). A request that names one of several files ("summarize report.pdf") reads only that file; a request about a part ("the main idea of section 3") is still answered from the passages that match; files of more than 48 parts in all (about 670 KB of text) are not read this way. The switch is in Settings > Documents.

Smaller: a search that failed no longer says that "no passage matched".

Everything else is as in [v0.1.11](https://github.com/AizenKai1001/forgeinfer/releases/tag/v0.1.11).

Unsigned binaries. Studio has been run on Windows 11 with an RTX 4060 and on Ubuntu 24.04 (X11) with an RTX 2060 SUPER; the macOS build is compiled and unit-tested by CI but nobody has run its window yet.
