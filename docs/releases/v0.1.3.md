## Forge Studio and ForgeInfer v0.1.3 (pre-release)

The longest context the card allows, faster decoding at long context, and a compressed cache that keeps its quality. Measured on an RTX 2060 SUPER (8 GB); the numbers on an RTX 4060 were not remeasured for this release.

**Context as long as the card can hold**
- `--ctx auto` (Studio: Settings, context length "auto"; the **Longest possible** button) opens the longest context that fits the video memory next to the weights, at most what the model was trained for (`FORGE_CTX_MAX` lowers the cap). Qwen3.5-4B Q4_K_M on an 8 GB card that another program already holds 0.9 GB of: 95,232 tokens with the 16-bit KV cache, 144,384 with 8-bit, 234,496 with 4-bit (the model's own limit is 262,144); the 9B: 30,720, 44,032 and 60,416. A planted fact was found at 187,448 and at 226,448 prompt tokens (`tools/needle_check.py`; the prompts took 469 and 666 seconds to read on the older card, decoding at that depth ran at 21 and 18 tokens/s). The engine prints the context it opened and the model list reports it (`meta.n_ctx`), so Studio's "N of M tokens" line is right.
- **What the compressed cache costs** (new table in [PERFORMANCE.md](https://github.com/AizenKai1001/forgeinfer/blob/main/docs/PERFORMANCE.md#long-contexts)): 8-bit is free (KL 0.0000 to 0.0005, the same top-1 token in 99.4 to 99.95 % of positions), 8-bit keys with 4-bit values (`--kv k8v4`, 40 percent of the 16-bit memory) stays within 1.5 percent of the top-1 choices on the dense Qwen3-4B and the hybrid 4B and 9B, and the all-4-bit cache is fine on the hybrids (97.4 to 99.0 %) but costs the dense Qwen3-4B 3 to 6 percent. Studio's **Longest possible** therefore uses `k8v4`, and the KV list has the new entry.
- **A conversation longer than the context** (Studio, new setting): by default the oldest turns are left out of what the model reads once the chat no longer fits, by whole turns and down to 70 percent of the context so that the engine's memory of the chat stays valid for the next messages; they stay on screen above a marker line. The other choice shows the server's "context too long" error as before.

**Faster decoding at long context**
- The decode attention of a model with four query heads per key-value head (Qwen3, Qwen3.5) now runs one block per key-value head that all of its query heads share (`attn_gqa_impl`): a key or value row is loaded and decoded once, and the sums over the lanes of the heads of a position come out of one butterfly (6 shuffles instead of 20). The partial results are bit-identical to the one-head kernels' (`crates/forge-gpu/tests/attn_gqa.rs`: 9,600 values in 17 layouts; `attn_gqa_model.rs`: whole models, tokens and logits bit for bit). Qwen3.5-4B decode, tokens/s, at 16,384 / 32,768 / 65,536 positions: fp16 cache 95 / 80 / 60 to 102 / 90 / 72; 8-bit 83 / 64 / 44 to 97 / 82 / 62; 4-bit 82 / 63 / 43 to 97 / 81 / 62. Used from 32 blocks (key-value heads times splits of 1,024 positions: 8 splits for four key-value heads; `FORGE_ATTN_GQA=0` turns it off); the dense Qwen3-4B at 8,192 positions: 58 to 74 tokens/s (fp16).
- With a compressed cache the decode attention reads the store directly instead of dequantizing the whole context into a scratch layer for every layer and token (`FORGE_KV_FUSED=0` brings the pass back).
- `FORGE_KV_GROUP` accepts groups down to 8 values per scale (smaller groups help the 4-bit keys of a dense model only partly).

**Tools**: `tools/needle_check.py` takes the server's context from `FORGE_CTX` (a number or `auto`).

Unsigned binaries. Studio has been run on Windows 11 with an RTX 4060 and on Ubuntu 24.04 (X11) with an RTX 2060 SUPER; the macOS build is compiled and unit-tested by CI but nobody has run its window yet.
