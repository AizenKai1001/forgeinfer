## Forge Studio and ForgeInfer v0.1.14 (pre-release)

**Scanned PDFs can be asked about, on Windows.** A scan has pages that are only pictures, so there was no text to read and Studio said so. Now Studio takes the picture out of each page and Windows' own text recognition (`Windows.Media.Ocr`, for the languages of your account, the same engine as the Snipping Tool's text actions) reads it: nothing is downloaded and nothing leaves the computer. A PDF that is partly text and partly scan is read page by page, each page the way it is. Pictures that are JPEG files or raw 8-bit gray or colour pixels or 1-bit black and white are read; fax-compressed pictures (CCITT, JBIG2), JPEG 2000 and palettes are not, and the message says so. On macOS and Linux there is no such engine built in and a scan says that it cannot be read.

Tried on a real 3-page copier scan (recognized in 0.8 seconds, clean text; its content is not copied anywhere) and on two PDFs made for the test, one of JPEG and one of Flate-compressed pixels: the lines came out whole, with one wrong space inside an identifier ("INV-7731 -QX"), and a 1.7B model answered a question about the scan correctly. A hand drawn paper prototype gave no text: there was none. The recognition is as good as Windows' (printed text well, handwriting poorly).

Also: an attached file in the chat can be clicked to see the text that was taken out of it (the start of it), so that a PDF, a spreadsheet or a scan that comes out differently from how it looks is noticed. The reader code survived 600,000 rounds of random markup in a fuzz test without a panic.

Everything else is as in [v0.1.13](https://github.com/AizenKai1001/forgeinfer/releases/tag/v0.1.13).

Unsigned binaries. Studio has been run on Windows 11 with an RTX 4060 and on Ubuntu 24.04 (X11) with an RTX 2060 SUPER; the macOS build is compiled and unit-tested by CI but nobody has run its window yet.
