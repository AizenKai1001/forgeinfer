## Forge Studio and ForgeInfer v0.1.6 (pre-release)

Embeddings: the engine now answers OpenAI's `POST /v1/embeddings` for **nomic-embed-text-v1.5**, the embedding model LM Studio ships, and Forge Studio can load it.

**The route.** `forge serve nomic-embed-text-v1.5.Q4_K_M.gguf` serves the embeddings on their own (on the GPU when there is one that works, else on the CPU); `forge serve chat-model.gguf --embedding-model nomic-embed-text-v1.5.Q4_K_M.gguf` serves both from one process (the embedder stays on the CPU unless `--embedding-device gpu`, so the chat engine keeps the card to itself). `input` is a string or a list of up to 2,048 texts, `dimensions` keeps the first N numbers (64 to 768, renormalised), `encoding_format` is `float` or `base64` (what the OpenAI SDKs ask for), and `/v1/models` lists the model. The task prefixes of the model (`search_document: `, `search_query: `, `clustering: `, `classification: `) are part of the text. `forge embed MODEL TEXT...` prints the cosines between texts. Details: [EMBEDDINGS.md](https://github.com/AizenKai1001/forgeinfer/blob/main/docs/EMBEDDINGS.md).

**Written from scratch like the rest**: a BERT WordPiece tokenizer in `forge-tok`, a CPU encoder in the new `forge-embed` crate (AVX2), and a GPU encoder in `forge-embed-gpu` (fp16 weights, the engine's tensor-core GEMMs, new small kernels in `encoder.cu`) that packs the tokens of many texts into one pass without padding, so a list of short texts is one fast pass instead of many slow ones.

**Checked** against independent things: token ids equal Hugging Face's `BertTokenizer` on 23 texts (English, accents, CJK, Hangul, emoji, control characters, the empty string); vectors equal a numpy implementation written from the architecture (CPU cosine 1.0000000, GPU 0.999999 or better, the same digits on an RTX 2060 SUPER and an RTX 4060); llama.cpp running the same weights in f32 agrees to five digits on 22 of the 23 texts (on the 23rd its WordPiece makes 18 tokens of a Hangul and kana text where Hugging Face's makes 25; the engine follows Hugging Face). On the quantized file llama.cpp's own vectors are 0.9935 from these (median), which is not an error on either side: its CPU backend rounds every activation vector to 8 bits and that rounding is chaotic through twelve layers (two emulated runs whose inputs differ by 1e-7 end 0.997 apart).

**Speed** (Q4_K_M file): 80,000 tokens/s on an RTX 4060 and 70,000 on an RTX 2060 SUPER for packs of 26-token texts (30,000 / 27,000 at 514 tokens, 18,000 / 16,000 at 1,023), against 790 tokens/s on 8 CPU threads; 23 texts (633 tokens) take 13 ms through HTTP on the 4060. The weights take 275 MB of video memory. The attention kernel of the encoder runs on the CUDA cores and limits long texts; a tensor-core kernel is on the [roadmap](https://github.com/AizenKai1001/forgeinfer/blob/main/docs/ROADMAP.md), with the other encoder families (bert, bge, e5, gte).

**Forge Studio**: an embedding model is a supported model; **Load** it and the Chat screen becomes an embedding playground (type lines, see how close each is to the first one, a colour grid of every pair, Copy vectors), and the Local server screen shows `curl` and Python snippets for `/v1/embeddings`.

Everything else is as in [v0.1.5](https://github.com/AizenKai1001/forgeinfer/releases/tag/v0.1.5).

Unsigned binaries. Studio has been run on Windows 11 with an RTX 4060 and on Ubuntu 24.04 (X11) with an RTX 2060 SUPER; the macOS build is compiled and unit-tested by CI but nobody has run its window yet.
