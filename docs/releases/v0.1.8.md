## Forge Studio and ForgeInfer v0.1.8 (pre-release)

**PDF, Word and PowerPoint files in chat with documents.** Drop a `.pdf`, `.docx` or `.pptx` file on Forge Studio's window like a text file: Studio reads its text (the text layer of a PDF, the paragraphs of a Word file, the slides of a PowerPoint file, in order) on a thread of its own, and from there the file is handled as in v0.1.7: sent whole when it fits the context, searched with the embedding model when it does not. A real 8-page paper (Bellard's NNCP report, 16,000 characters) opens in 0.15 s and a 4,096-token context answers questions about it. PDF text gets a little tidying: ligature characters are spelled out ("ﬁ" becomes "fi", so a search for "office" finds "oﬃce"), words that a line break cut with a hyphen are put together again, page breaks and runs of blank lines are folded. A scanned PDF has no text layer; Studio says so instead of attaching nothing (character recognition is not part of it). Parsers: `pdf-extract` and `zip`, pure Rust.

**Missing from the v0.1.7 notes.** A question that matches nothing well (a request for a summary) already got the two nearest passages in v0.1.7, marked as weak matches (cosine 0.4 to 0.6) with a prompt that tells the model they may not be relevant; the model bar says "documents" when an embedding model runs next to the chat model; `--send` of Studio's test options can be given several times for multi-turn checks.

Everything else is as in [v0.1.7](https://github.com/AizenKai1001/forgeinfer/releases/tag/v0.1.7).

Unsigned binaries. Studio has been run on Windows 11 with an RTX 4060 and on Ubuntu 24.04 (X11) with an RTX 2060 SUPER; the macOS build is compiled and unit-tested by CI but nobody has run its window yet.
