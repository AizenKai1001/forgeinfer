## Forge Studio and ForgeInfer v0.1.2 (pre-release)

Long chats stay quick and going back to an earlier chat is cheap, and the HTTP server is hardened. Measured on an RTX 2060 SUPER with a 6,400-token document in the chat; the numbers on an RTX 4060 were not remeasured for this release.

**Chats at long context**
- The decode attention of dense and hybrid models runs in split-KV blocks from a session context of 1,024 positions (it ran one block per head and read the KV cache at 49 GB/s; the split kernels used to exist only for contexts beyond 11,000 positions). Qwen3-4B Q6_K after 6,400 positions: 29 to 13 ms per token; Qwen3.5-4B: 12.7 to 8.8 ms. `FORGE_ATTN_SPLIT=0` keeps the old kernel where it can launch.
- A dense model's multi-row path takes fewer tokens as the context grows (every row of it reads the whole KV cache): the 40 new tokens of a chat follow-up read in 104 ms instead of 900, and the whole follow-up request takes 0.43 s instead of 1.4 to 1.6. `FORGE_MROW_CTX=0` keeps the fixed limit.
- The attention of that path shares the loads of keys and values between four rows (`attn_split_rows4_kernel`, bit-identical to the one-row kernel; `FORGE_ATTN_ROWS=0` turns it off): an answer that copies text out of a 6,400-token document with prompt lookup runs at 134 instead of 109 tokens/s.
- **Prompt cache** (`--prompt-cache-mb`, `FORGE_PROMPT_CACHE_MB`, default 2,048, 0 = off): the conversation the GPU holds is copied to page-locked host memory when a request is about to discard most of it, and comes back when a later request continues it. Return to a 6,400-token chat: 3.46 to 0.58 s (dense 4B), 3.14 to 0.38 s (hybrid 4B), 5.25 to 0.52 s (Qwen3.5-9B with its head); the answers equal those of the engine's own reuse of the previous turn (`tools/cache_check.py`; `tools/cache_soak.py` visits several chats in a random order; GPU round-trip tests for dense and hybrid models with the fp16 and the int8 cache).
- Forge Studio: a **Chat memory** setting, and the line under an answer says how many prompt tokens the engine already had.

**Server hardening**: request bodies up to 8 MiB (also chunked ones), the head of a request within 30 s and its body within 120 s (HTTP 408), 256 connections, constant-time API key comparison, and a server on a loopback address answers only requests that name a local host (DNS rebinding; `FORGE_ALLOWED_HOSTS` for a reverse proxy). Special-token strings inside chat messages and tool definitions are defused before the template is rendered, so a pasted document cannot end a turn or open a system turn (`FORGE_PARSE_SPECIAL_IN_MESSAGES=1` restores parsing).

**Tools**: `tools/cache_check.py`, `tools/cache_soak.py`, `tools/snapshot_check.py`, `tools/followup_probe.py`, `tools/injection_check.py`, `tools/tokenizer_parity.py` (43 of 45 awkward texts give the ids of llama.cpp's tokenizer in three vocabularies; the other two differ by design).

Unsigned binaries. Studio has been run on Windows 11 with an RTX 4060 and on Ubuntu 24.04 (X11) with an RTX 2060 SUPER; the macOS build is compiled and unit-tested by CI but nobody has run its window yet.
